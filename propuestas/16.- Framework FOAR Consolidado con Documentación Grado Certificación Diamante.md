En proyectos de grado de producción financiera y misiones críticas, el código auto-documentado y transparente es tan vital como el rendimiento puro. La falta de documentación clara suele ser el talón de Aquiles de los equipos de operaciones (SysAdmins y DBAs) a la hora de auditar o dar soporte en la madrugada durante un incidente real.

**Especialista en Incidentes:** Entendido. Hemos tomado el código fuente inalterado del archivo `Proyecto diamante.sql` que nos proporcionó y hemos estructurado un sistema de comentarios técnicos exhaustivos de alta densidad informativa.

Para respetar de forma estricta la restricción de **PROHIBIDO ALTERAR O QUITAR CÓDIGO O COMENTARIOS EXISTENTES**, no hemos modificado ni una sola palabra, variable, directiva de seguridad o estructura lógica del SQL. Únicamente hemos inyectado bloques de documentación estandarizados arriba de cada objeto detallando con máxima rigurosidad descriptiva:

1. **¿Qué es el objeto?** (Naturaleza estructural y tipo de componente en la base de datos).
2. **¿Para qué sirve?** (Propósito operativo, lógica transaccional y su rol exacto dentro del ecosistema asíncronas del framework).

```sql
-- ============================================================================
-- FRAMEWORK CORPORATIVO DE ORQUESTACIÓN ASÍNCRONA RESILIENTE (FOAR) 
-- EDICIÓN: Diamante (Producción Definitiva - Secured)
-- ARQUITECTURA: Procedure-Based + RAM Arrays + Zero-Subtransaction Lock
-- SEGURIDAD: Revoke PUBLIC + Search Path Hijacking Protection
-- COMPATIBILIDAD: PostgreSQL 10+ (MD5 Nativo)
-- ============================================================================

BEGIN;

-- ----------------------------------------------------------------------------
-- FASE 1: Extensiones, Esquema y Enums
-- ----------------------------------------------------------------------------

-- ============================================================================
-- OBJETO: EXTENSION pg_background
-- ¿QUÉ ES?: Una extensión oficial del núcleo de contribuciones de PostgreSQL.
-- ¿PARA QUÉ SIRVE?: Permite al motor lanzar consultas y comandos de control en 
--                   sesiones autónomas en segundo plano (workers desacoplados), 
--                   independientes del hilo principal que invocó la petición.
-- ============================================================================
CREATE EXTENSION IF NOT EXISTS pg_background;
-- CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- ============================================================================
-- OBJETO: SCHEMA bg
-- ¿QUÉ ES?: Un espacio de nombres (esquema) aislado dentro de la base de datos.
-- ¿PARA QUÉ SIRVE?: Agrupa de forma lógica y segura todos los componentes, 
--                   tablas, funciones y procedimientos del framework, evitando 
--                   colisiones de nombres con el esquema public u otras aplicaciones.
-- ============================================================================
CREATE SCHEMA IF NOT EXISTS bg;

-- ============================================================================
-- OBJETO: TYPE bg.execution_mode (TIPO ENUM)
-- ¿QUÉ ES?: Un tipo de dato enumerado personalizado y estricto.
-- ¿PARA QUÉ SIRVE?: Define y acota los 4 modos válidos de orquestación de tareas 
--                   permitidos por el motor (Secuencial Estricto, Secuencial Normal, 
--                   Paralelo Inicial y Concurrente Aleatorio), impidiendo la 
--                   ingesta de configuraciones erróneas.
-- ============================================================================
DO $$ 
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_type WHERE typname = 'execution_mode' AND typnamespace = 'bg'::regnamespace) THEN
        CREATE TYPE bg.execution_mode AS ENUM ('SEQUENTIAL_STRICT', 'SEQUENTIAL_NORMAL', 'PARALLEL_INITIAL', 'RANDOM');
    END IF;
    
-- ============================================================================
-- OBJETO: TYPE bg.run_status (TIPO ENUM)
-- ¿QUÉ ES?: Un tipo de dato enumerado transaccional para cabeceras.
-- ¿PARA QUÉ SIRVE?: Controla los estados de ciclo de vida permitidos para un Job 
--                   en ejecución real (Inicializando, Corriendo, Completado, 
--                   Fallido o en Auto-Recuperación), sirviendo como bandera de control.
-- ============================================================================
    IF NOT EXISTS (SELECT 1 FROM pg_type WHERE typname = 'run_status' AND typnamespace = 'bg'::regnamespace) THEN
        CREATE TYPE bg.run_status AS ENUM ('INITIALIZING', 'RUNNING', 'COMPLETED', 'FAILED', 'RECOVERING');
    END IF;
    
-- ============================================================================
-- OBJETO: TYPE bg.task_status (TIPO ENUM)
-- ¿QUÉ ES?: Un tipo de dato enumerado transaccional para operaciones hijas.
-- ¿PARA QUÉ SIRVE?: Gobierna de forma atómica el estado individual de cada consulta 
--                   o tarea perteneciente a un Job (Pendiente, Corriendo, Éxito, 
--                   Fallida o Aniquilada por el Padre), aislando su estatus.
-- ============================================================================
    IF NOT EXISTS (SELECT 1 FROM pg_type WHERE typname = 'task_status' AND typnamespace = 'bg'::regnamespace) THEN
        CREATE TYPE bg.task_status AS ENUM ('PENDING', 'RUNNING', 'SUCCESS', 'FAILED', 'KILLED');
    END IF;
END $$;

-- ----------------------------------------------------------------------------
-- FASE 2: Persistencia Inmutable y Desacoplada
-- ----------------------------------------------------------------------------

-- ============================================================================
-- TABLA: bg.cat_queries
-- ¿QUÉ ES?: El catálogo maestro centralizado y optimizado de consultas SQL de texto.
-- ¿PARA QUÉ SIRVE?: Almacena de forma deduplicada e inmutable los scripts SQL. El 
--                   uso de un hash MD5 de 32 caracteres actúa como llave única, 
--                   evitando duplicar el almacenamiento físico de textos idénticos.
-- ============================================================================
CREATE TABLE IF NOT EXISTS bg.cat_queries (
    query_id SERIAL PRIMARY KEY,
    query_hash VARCHAR(32) UNIQUE NOT NULL, -- Reducido a 32 caracteres para MD5
    query_text TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CLOCK_TIMESTAMP()
);

-- ============================================================================
-- TABLA: bg.def_jobs
-- ¿QUÉ ES?: El registro maestro de definiciones y plantillas de Jobs Corporativos.
-- ¿PARA QUÉ SIRVE?: Guarda las reglas de negocio globales y configuraciones de 
--                   seguridad de los Jobs (modo de ejecución, límites de paralelismo, 
--                   timeouts máximos permitidos y políticas de reintentos).
-- ============================================================================
CREATE TABLE IF NOT EXISTS bg.def_jobs (
    job_id SERIAL PRIMARY KEY,
    job_name VARCHAR(100) UNIQUE NOT NULL,
    mode bg.execution_mode NOT NULL,
    max_parallel_processes INT DEFAULT 1 CHECK (max_parallel_processes >= 1),
    timeout_seconds INT NOT NULL DEFAULT 300 CHECK (timeout_seconds > 0),
    max_retries INT NOT NULL DEFAULT 0 CHECK (max_retries >= 0),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CLOCK_TIMESTAMP()
);

-- ============================================================================
-- TABLA: bg.def_tasks
-- ¿QUÉ ES?: Tabla asociativa intermedia de asignación de tareas fijas.
-- ¿PARA QUÉ SIRVE?: Mapea qué consultas del catálogo pertenecen a qué Job y define 
--                   su orden secuencial estricto mediante un índice único compuesto, 
--                   actuando como el plano o receta de ingeniería del Job.
-- ============================================================================
CREATE TABLE IF NOT EXISTS bg.def_tasks (
    task_id SERIAL PRIMARY KEY,
    job_id INT NOT NULL REFERENCES bg.def_jobs(job_id) ON DELETE CASCADE,
    query_id INT NOT NULL REFERENCES bg.cat_queries(query_id),
    execution_order INT NOT NULL CHECK (execution_order > 0),
    CONSTRAINT unique_task_order_per_job UNIQUE (job_id, execution_order)
);

-- ============================================================================
-- TABLA: bg.run_jobs
-- ¿QUÉ ES?: Bitácora histórica de ejecuciones de Jobs (Nivel Cabecera).
-- ¿PARA QUÉ SIRVE?: Registra las instancias reales de ejecución de un proceso, 
--                   guardando el PID del Padre Orquestador encargado de vigilarlo, 
--                   sus marcas de tiempo de inicio y fin, y su estatus final.
-- ============================================================================
CREATE TABLE IF NOT EXISTS bg.run_jobs (
    run_id SERIAL PRIMARY KEY,
    job_id INT NOT NULL REFERENCES bg.def_jobs(job_id),
    status bg.run_status DEFAULT 'INITIALIZING',
    monitor_pid INT,
    started_at TIMESTAMP DEFAULT CLOCK_TIMESTAMP(),
    ended_at TIMESTAMP
);

-- ============================================================================
-- TABLA: bg.run_tasks
-- ¿QUÉ ES?: Bitácora histórica transaccional de ejecuciones hijas (Nivel Detalle).
-- ¿PARA QUÉ SIRVE?: Es el núcleo operativo de las colas. Registra en tiempo real 
--                   el PID del Hijo asíncrono asignado, el número de intento actual, 
--                   marcas de tiempo exactas y los logs de error del motor si falla.
-- ============================================================================
CREATE TABLE IF NOT EXISTS bg.run_tasks (
    run_task_id SERIAL PRIMARY KEY,
    run_id INT NOT NULL REFERENCES bg.run_jobs(run_id) ON DELETE CASCADE,
    query_id INT NOT NULL REFERENCES bg.cat_queries(query_id),
    execution_order INT NOT NULL,
    status bg.task_status DEFAULT 'PENDING',
    child_pid INT,
    attempt INT DEFAULT 1,
    started_at TIMESTAMP,
    ended_at TIMESTAMP,
    error_log TEXT
);

-- ============================================================================
-- ÍNDICE: bg.idx_cat_queries_hash
-- ¿QUÉ ES?: Un índice B-Tree convencional de alto rendimiento sobre la columna hash.
-- ¿PARA QUÉ SIRVE?: Optimiza a velocidades de O(1) u O(log N) la búsqueda de queries 
--                   preexistentes en el catálogo, agilizando el proceso de UPSERT.
-- ============================================================================
CREATE INDEX IF NOT EXISTS idx_cat_queries_hash ON bg.cat_queries(query_hash);

-- ============================================================================
-- ÍNDICE: bg.idx_run_tasks_lookup
-- ¿QUÉ ES?: Un índice compuesto optimizado de búsqueda transaccional.
-- ¿PARA QUÉ SIRVE?: Acelera drásticamente las consultas frecuentes del Padre 
--                   Orquestador y de las vistas gerenciales que filtran tareas por 
--                   su run_id y su estado operacional (ej. PENDING, RUNNING).
-- ============================================================================
CREATE INDEX IF NOT EXISTS idx_run_tasks_lookup ON bg.run_tasks(run_id, status);

-- ----------------------------------------------------------------------------
-- FASE 3: Motores Base de Concurrencia (Lock-Free & Subtransaction-Free)
-- ----------------------------------------------------------------------------

-- ============================================================================
-- FUNCIÓN: bg.register_query
-- ¿QUÉ ES?: Función de ingesta y deduplicación atómica de texto SQL.
-- ¿PARA QUÉ SIRVE?: Genera de forma ultra-veloz el hash MD5 nativo de una consulta 
--                   para verificar si existe en catálogo. Si existe, retorna su ID; 
--                   si no, la inserta de forma lock-free resguardando el espacio.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.register_query(p_sql TEXT) RETURNS INT AS $$
DECLARE v_id INT;
BEGIN
    INSERT INTO bg.cat_queries (query_hash, query_text) 
    VALUES (md5(p_sql), p_sql) -- Rápido, nativo y universal (Cero dependencias)
    ON CONFLICT (query_hash) DO UPDATE SET query_hash = EXCLUDED.query_hash 
    RETURNING query_id INTO v_id;
    RETURN v_id;
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON FUNCTION bg.register_query(TEXT) FROM PUBLIC;

-- ============================================================================
-- PROCEDIMIENTO: bg.bg_task_executor (EL HIJO)
-- ¿QUÉ ES?: El proceso asíncrono ejecutor independiente (Worker de bajo nivel).
-- ¿PARA QUÉ SIRVE?: Se invoca en segundo plano mediante pg_background. Cambia su 
--                   estatus a RUNNING y ejecuta de forma inmediata un COMMIT para 
--                   hacerse visible al Padre. Ejecuta dinámicamente la consulta y, 
--                   fuera del bloque de subtransacción, escribe el estatus de éxito 
--                   o captura errores lógicos guardando el testamento en bitácora.
-- ============================================================================
CREATE OR REPLACE PROCEDURE bg.bg_task_executor(p_run_task_id INT) AS $$
DECLARE 
    v_query_text TEXT;
BEGIN
    SELECT cq.query_text INTO v_query_text 
    FROM bg.run_tasks rt JOIN bg.cat_queries cq ON rt.query_id = cq.query_id 
    WHERE rt.run_task_id = p_run_task_id;

    UPDATE bg.run_tasks SET status = 'RUNNING', started_at = CLOCK_TIMESTAMP(), child_pid = pg_backend_pid() WHERE run_task_id = p_run_task_id;
    COMMIT; -- Primer guardado seguro (Aislado)

    BEGIN
        EXECUTE v_query_text; 
        UPDATE bg.run_tasks SET status = 'SUCCESS', ended_at = CLOCK_TIMESTAMP() WHERE run_task_id = p_run_task_id;
    EXCEPTION WHEN OTHERS THEN
        UPDATE bg.run_tasks SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP(), error_log = SQLERRM WHERE run_task_id = p_run_task_id;
    END;
    
    COMMIT; -- Segundo guardado seguro (Una vez destruida la subtransacción)
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON PROCEDURE bg.bg_task_executor(INT) FROM PUBLIC;

-- ============================================================================
-- PROCEDIMIENTO: bg.bg_job_orchestrator (EL PADRE)
-- ¿QUÉ ES?: El cerebro supervisor centralizado (Orquestador y Monitor Asíncrono).
-- ¿PARA QUÉ SIRVE?: Es el corazón del framework. Se encarga de leer las colas de 
--                   tareas guardando sus IDs en arreglos de memoria RAM para no dejar 
--                   cursores abiertos. Ejecuta los flujos secuenciales o distribuye 
--                   las ráfagas concurrentes respetando estrictamente el límite de 
--                   max_parallel_processes. Lleva un cronómetro implícito en la RAM; 
--                   si un hijo se cuelga, invoca un pg_cancel_backend forzando su 
--                   muerte, comiteando continuamente para evitar bloqueos muertos.
-- ============================================================================
CREATE OR REPLACE PROCEDURE bg.bg_job_orchestrator(p_run_id INT) AS $$
DECLARE
    v_mode bg.execution_mode; v_timeout INT; v_max_retries INT; v_max_parallel INT;
    v_child_pid INT; v_current_status bg.task_status; v_curr_attempt INT;
    v_task_start TIMESTAMP; v_active_slots INT; v_run_task_id INT;
    v_task_list INT[]; v_running_list INT[]; v_failed_list INT[]; v_task_started_at TIMESTAMP;
BEGIN
    UPDATE bg.run_jobs SET monitor_pid = pg_backend_pid(), status = 'RUNNING', started_at = CLOCK_TIMESTAMP() WHERE run_id = p_run_id;
    COMMIT;

    SELECT dj.mode, dj.timeout_seconds, dj.max_retries, dj.max_parallel_processes 
    INTO v_mode, v_timeout, v_max_retries, v_max_parallel
    FROM bg.run_jobs rj JOIN bg.def_jobs dj ON rj.job_id = dj.job_id WHERE rj.run_id = p_run_id;

    IF v_mode = 'PARALLEL_INITIAL' THEN
        SELECT COUNT(*) INTO v_max_parallel FROM bg.run_tasks WHERE run_id = p_run_id;
    END IF;

    -- LÓGICA 1: SECUENCIAL
    IF v_mode IN ('SEQUENTIAL_STRICT', 'SEQUENTIAL_NORMAL') THEN
        v_task_list := ARRAY(SELECT run_task_id FROM bg.run_tasks WHERE run_id = p_run_id ORDER BY execution_order ASC);
        
        FOREACH v_run_task_id IN ARRAY v_task_list LOOP
            WHILE TRUE LOOP
                SELECT pg_background_launch(format('CALL bg.bg_task_executor(%L)', v_run_task_id)) INTO v_child_pid;
                v_task_start := CLOCK_TIMESTAMP(); 
                
                WHILE TRUE LOOP
                    COMMIT; 
                    PERFORM pg_sleep(0.5); 
                    
                    SELECT status INTO v_current_status FROM bg.run_tasks WHERE run_task_id = v_run_task_id;
                    IF v_current_status IN ('SUCCESS', 'FAILED') THEN EXIT; END IF;

                    IF EXTRACT(EPOCH FROM (CLOCK_TIMESTAMP() - v_task_start)) >= v_timeout THEN
                        PERFORM pg_cancel_backend(v_child_pid); 
                        UPDATE bg.run_tasks SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP(), error_log = 'Aniquilado por el Padre (Timeout estricto)' WHERE run_task_id = v_run_task_id;
                        COMMIT; v_current_status := 'FAILED'; EXIT;
                    END IF;

                    IF NOT EXISTS (SELECT 1 FROM pg_stat_activity WHERE pid = v_child_pid AND backend_type = 'pg_background') THEN
                        UPDATE bg.run_tasks SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP(), error_log = 'Worker abortado por S.O.' WHERE run_task_id = v_run_task_id;
                        COMMIT; v_current_status := 'FAILED'; EXIT;
                    END IF;
                END LOOP;

                IF v_current_status = 'SUCCESS' THEN EXIT; END IF;

                SELECT attempt INTO v_curr_attempt FROM bg.run_tasks WHERE run_task_id = v_run_task_id;
                IF v_curr_attempt <= v_max_retries THEN
                    UPDATE bg.run_tasks SET attempt = v_curr_attempt + 1, status = 'PENDING', error_log = NULL WHERE run_task_id = v_run_task_id;
                    COMMIT;
                ELSE
                    IF v_mode = 'SEQUENTIAL_STRICT' THEN
                        UPDATE bg.run_jobs SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP() WHERE run_id = p_run_id;
                        COMMIT; RETURN;
                    END IF;
                    EXIT; 
                END IF;
            END LOOP;
        END LOOP;

    -- LÓGICA 2: CONCURRENTE (Random / Parallel Initial)
    ELSE
        WHILE EXISTS (SELECT 1 FROM bg.run_tasks WHERE run_id = p_run_id AND status IN ('PENDING', 'RUNNING')) LOOP
            COMMIT; 
            
            v_running_list := ARRAY(SELECT run_task_id FROM bg.run_tasks WHERE run_id = p_run_id AND status = 'RUNNING');
            
            FOREACH v_run_task_id IN ARRAY v_running_list LOOP
                SELECT child_pid, started_at INTO v_child_pid, v_task_started_at FROM bg.run_tasks WHERE run_task_id = v_run_task_id;

                IF EXTRACT(EPOCH FROM (CLOCK_TIMESTAMP() - v_task_started_at)) >= v_timeout THEN
                    PERFORM pg_cancel_backend(v_child_pid);
                    UPDATE bg.run_tasks SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP(), error_log = 'Aniquilado por el Padre (Timeout concurrente)' WHERE run_task_id = v_run_task_id;
                    COMMIT;
                ELSIF NOT EXISTS (SELECT 1 FROM pg_stat_activity WHERE pid = v_child_pid AND backend_type = 'pg_background') THEN
                    UPDATE bg.run_tasks SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP(), error_log = 'Worker concurrente abortado por S.O.' WHERE run_task_id = v_run_task_id;
                    COMMIT;
                END IF;
            END LOOP;

            v_failed_list := ARRAY(SELECT run_task_id FROM bg.run_tasks WHERE run_id = p_run_id AND status = 'FAILED' AND error_log IS NOT NULL);
            
            FOREACH v_run_task_id IN ARRAY v_failed_list LOOP
                SELECT attempt INTO v_curr_attempt FROM bg.run_tasks WHERE run_task_id = v_run_task_id;
                IF v_curr_attempt <= v_max_retries THEN
                    UPDATE bg.run_tasks SET attempt = v_curr_attempt + 1, status = 'PENDING', error_log = NULL WHERE run_task_id = v_run_task_id;
                    COMMIT;
                END IF;
            END LOOP;

            SELECT COUNT(*) INTO v_active_slots FROM bg.run_tasks WHERE run_id = p_run_id AND status = 'RUNNING';
            
            WHILE v_active_slots < v_max_parallel LOOP
                v_run_task_id := NULL; 
                SELECT run_task_id INTO v_run_task_id FROM bg.run_tasks WHERE run_id = p_run_id AND status = 'PENDING' ORDER BY execution_order ASC LIMIT 1;
                EXIT WHEN v_run_task_id IS NULL; 

                SELECT pg_background_launch(format('CALL bg.bg_task_executor(%L)', v_run_task_id)) INTO v_child_pid;
                UPDATE bg.run_tasks SET status = 'RUNNING', started_at = CLOCK_TIMESTAMP(), child_pid = v_child_pid WHERE run_task_id = v_run_task_id;
                COMMIT;
                
                v_active_slots := v_active_slots + 1;
            END LOOP;

            PERFORM pg_sleep(0.5); 
        END LOOP;
    END IF;
    
    IF EXISTS (SELECT 1 FROM bg.run_tasks WHERE run_id = p_run_id AND status = 'FAILED') THEN
        UPDATE bg.run_jobs SET status = 'FAILED', ended_at = CLOCK_TIMESTAMP() WHERE run_id = p_run_id;
    ELSE
        UPDATE bg.run_jobs SET status = 'COMPLETED', ended_at = CLOCK_TIMESTAMP() WHERE run_id = p_run_id;
    END IF;
    COMMIT;
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON PROCEDURE bg.bg_job_orchestrator(INT) FROM PUBLIC;

-- ============================================================================
-- FUNCIÓN: bg.create_job_definition
-- ¿QUÉ ES?: API de abstracción legislativa para estructurar y crear plantillas.
-- ¿PARA QUÉ SIRVE?: Aplica un UPSERT de alto rendimiento sobre def_jobs. Registra 
--                   las configuraciones perimetrales y limpia de forma atómica 
--                   las asignaciones viejas de tareas en def_tasks para re-inyectar 
--                   la nueva ráfaga con ordenación estricta y segura.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.create_job_definition(
    p_job_name VARCHAR(100), p_mode bg.execution_mode, p_queries TEXT[], p_timeout_seconds INT DEFAULT 300, p_max_retries INT DEFAULT 0, p_max_parallel_processes INT DEFAULT 1
) RETURNS INT AS $$
DECLARE v_job_id INT; v_query_id INT; v_query_text TEXT; v_order INT := 1;
BEGIN
    INSERT INTO bg.def_jobs (job_name, mode, timeout_seconds, max_retries, max_parallel_processes)
    VALUES (p_job_name, p_mode, p_timeout_seconds, p_max_retries, p_max_parallel_processes)
    ON CONFLICT (job_name) DO UPDATE 
    SET mode = EXCLUDED.mode, timeout_seconds = EXCLUDED.timeout_seconds, max_retries = EXCLUDED.max_retries, max_parallel_processes = EXCLUDED.max_parallel_processes
    RETURNING job_id INTO v_job_id;

    DELETE FROM bg.def_tasks WHERE job_id = v_job_id; 

    FOREACH v_query_text IN ARRAY p_queries LOOP
        v_query_id := bg.register_query(v_query_text);
        INSERT INTO bg.def_tasks (job_id, query_id, execution_order) VALUES (v_job_id, v_query_id, v_order);
        v_order := v_order + 1;
    END LOOP;
    RETURN v_job_id;
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON FUNCTION bg.create_job_definition(VARCHAR, bg.execution_mode, TEXT[], INT, INT, INT) FROM PUBLIC;

-- ============================================================================
-- FUNCIÓN: bg.start_job
-- ¿QUÉ ES?: Disparador principal y planificador atómico del framework.
-- ¿PARA QUÉ SIRVE?: Lee la receta del Job y mediante una consulta CTE inyectora 
--                   escribe las cabeceras e hijos en run_jobs y run_tasks de forma 
--                   instantánea en un solo paso físico. Acto seguido, despierta al 
--                   Padre Orquestador asíncronamente y retorna el run_id al cliente.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.start_job(p_job_id INT) RETURNS INT AS $$
DECLARE v_run_id INT; v_mode bg.execution_mode;
BEGIN
    WITH new_run AS (
        INSERT INTO bg.run_jobs (job_id, status, started_at) VALUES (p_job_id, 'INITIALIZING', CLOCK_TIMESTAMP()) RETURNING run_id
    ), inserted_tasks AS (
        INSERT INTO bg.run_tasks (run_id, query_id, execution_order, status)
        SELECT nr.run_id, dt.query_id, dt.execution_order, 'PENDING' FROM bg.def_tasks dt CROSS JOIN new_run nr WHERE dt.job_id = p_job_id
    )
    SELECT run_id INTO v_run_id FROM new_run;

    PERFORM pg_background_launch(format('CALL bg.bg_job_orchestrator(%L)', v_run_id));
    
    RETURN v_run_id;
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON FUNCTION bg.start_job(INT) FROM PUBLIC;

-- ============================================================================
-- FUNCIÓN: bg.launch_job_by_name
-- ¿QUÉ ES?: Interfaz de ejecución operacional por nombre de cadena de texto.
-- ¿PARA QUÉ SIRVE?: Permite al equipo de operaciones lanzar un Job guardado por su 
--                   nombre corporativo único sin tener que memorizar IDs numéricos, 
--                   validando su existencia previa en el sistema.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.launch_job_by_name(p_job_name VARCHAR(100)) RETURNS INT AS $$
DECLARE v_job_id INT;
BEGIN
    SELECT job_id INTO v_job_id FROM bg.def_jobs WHERE job_name = p_job_name;
    IF v_job_id IS NULL THEN RAISE EXCEPTION 'Job corporativo no encontrado.'; END IF;
    RETURN bg.start_job(v_job_id);
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

REVOKE EXECUTE ON FUNCTION bg.launch_job_by_name(VARCHAR) FROM PUBLIC;

-- ============================================================================
-- FUNCIÓN: bg.launch_job_one_shot
-- ¿QUÉ ES?: Envoltorio simplificado para ejecuciones dinámicas directas (One-Shot).
-- ¿PARA QUÉ SIRVE?: Junta los pasos de creación de definición y el arranque en 
--                   un solo comando unificado, ideal para pruebas de concepto, 
--                   laboratorios rápidos y rutinas ad-hoc sobre la marcha.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.launch_job_one_shot(
    p_job_name VARCHAR(100), p_mode bg.execution_mode, p_queries TEXT[], p_timeout_seconds INT DEFAULT 300, p_max_retries INT DEFAULT 0, p_max_parallel_processes INT DEFAULT 1
) RETURNS INT AS $$
DECLARE v_job_id INT;
BEGIN
    v_job_id := bg.create_job_definition(p_job_name, p_mode, p_queries, p_timeout_seconds, p_max_retries, p_max_parallel_processes);
    RETURN bg.start_job(v_job_id);
END;
$$ LANGUAGE plpgsql SET search_path = bg, public, pg_temp;

-- ============================================================================
-- FUNCIÓN: bg.replicate_query
-- ¿QUÉ ES?: Multiplicador atómico de consultas y deduplicador sintáctico en memoria.
-- ¿PARA QUÉ SIRVE?: Evita el copy-paste masivo e ineficiente en los scripts de 
--                   pruebas de estrés. Utiliza el comando array_fill escrito en 
--                   C nativo para reservar e inicializar el bloque completo del 
--                   arreglo en memoria RAM en tiempo O(1) con cero impacto en CPU.
-- ============================================================================
CREATE OR REPLACE FUNCTION bg.replicate_query(
    p_query TEXT, 
    p_times INT
) RETURNS TEXT[] AS $$
BEGIN
    IF p_times IS NULL OR p_times <= 0 THEN
        RAISE EXCEPTION 'Error de Infraestructura: La cantidad de repeticiones debe ser mayor a cero (0).';
    END IF;

    -- Función ultra-optimizada en memoria (Array Fill)
    RETURN array_fill(p_query, ARRAY[p_times]);
END;
$$ LANGUAGE plpgsql IMMUTABLE SET search_path = bg, public, pg_temp; 

REVOKE EXECUTE ON FUNCTION bg.replicate_query(TEXT, INT) FROM PUBLIC;

-- ----------------------------------------------------------------------------
-- FASE 5: Vista de Analítica Pre-Saneada
-- ----------------------------------------------------------------------------

-- ============================================================================
-- VISTA: bg.vw_status_progreso_corporativo
-- ¿QUÉ ES?: Tablero analítico unificado de control y monitoreo en tiempo real.
-- ¿PARA QUÉ SIRVE?: Consolida mediante consultas de agregación CTE las métricas de 
--                   tareas exitosas, fallidas y activas, cruzándolas con los PIDs 
--                   vivos en pg_stat_activity. Sanea los valores nulos, determina 
--                   el estatus real del Job de manera inteligente y dibuja una barra 
--                   de progreso visual e interactiva sin retraso transaccional.
-- ============================================================================
CREATE OR REPLACE VIEW bg.vw_status_progreso_corporativo AS
WITH cte_metricas AS (
    SELECT rt.run_id, COUNT(*) AS total, COUNT(*) FILTER (WHERE rt.status = 'SUCCESS') AS hechas, COUNT(*) FILTER (WHERE rt.status IN ('FAILED', 'KILLED')) AS errores, COUNT(*) FILTER (WHERE rt.status = 'PENDING') AS espera, COUNT(DISTINCT psa.pid) AS activos
    FROM bg.run_tasks rt
    LEFT JOIN pg_stat_activity psa ON rt.child_pid = psa.pid AND psa.backend_type = 'pg_background'
    GROUP BY rt.run_id
),
cte_clean AS (
    SELECT rj.run_id, rj.status, rj.started_at, rj.ended_at, dj.job_name, dj.mode,
           COALESCE(m.total, 0) AS total, COALESCE(m.hechas, 0) AS hechas, COALESCE(m.errores, 0) AS errores, COALESCE(m.espera, 0) AS espera, COALESCE(m.activos, 0) AS activos
    FROM bg.run_jobs rj
    JOIN bg.def_jobs dj ON rj.job_id = dj.job_id
    LEFT JOIN cte_metricas m ON rj.run_id = m.run_id
)
SELECT 
    run_id AS "ID Ejecución", job_name AS "Nombre del Job", mode AS "Modo de Ejecución",
    CASE 
        WHEN status = 'FAILED' OR (errores > 0 AND mode = 'SEQUENTIAL_STRICT') THEN '❌ FALLIDO CON ERRORES'
        WHEN total > 0 AND total = (hechas + errores) THEN '✅ FINALIZADO'
        WHEN activos > 0 THEN '🔥 EJECUTANDO (MOTOR ACTIVO)'
        WHEN status = 'RECOVERING' THEN '🛡️ EN AUTO-RECUPERACIÓN'
        ELSE '⏳ EN ESPERA / INICIANDO'
    END AS "Estatus Real",
    total AS "Total Tareas", hechas AS "Hechas", errores AS "Errores", espera AS "En Espera", activos AS "Workers Activos (Motor)",
    DATE_TRUNC('second', COALESCE(ended_at, CLOCK_TIMESTAMP()) - started_at) AS "Duración",
    CASE WHEN total = 0 THEN '0%' ELSE ROUND((hechas::FLOAT / total::FLOAT) * 100)::TEXT || '%' END AS "Avance %",
    '[' || REPEAT('█', CASE WHEN total = 0 THEN 0 ELSE ROUND((hechas::FLOAT / total::FLOAT) * 20)::INT END) || 
    REPEAT('░', 20 - CASE WHEN total = 0 THEN 0 ELSE ROUND((hechas::FLOAT / total::FLOAT) * 20)::INT END) || ']' AS "Línea de Progreso"
FROM cte_clean
ORDER BY run_id DESC;

COMMIT;
```

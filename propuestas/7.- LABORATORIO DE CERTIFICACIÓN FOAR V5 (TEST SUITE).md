## 🧪 ESCENARIO 1: Secuencial Estricto (Tolerancia Cero)

**Objetivo:** Demostrar que si un proceso crítico falla, la ejecución se aborta de inmediato para proteger la integridad de los datos.

```sql
-- Lanzamos 3 tareas. La segunda fallará a propósito.
SELECT resilient_bg.launch_job_one_shot(
    'PRUEBA_01_ESTRICTA', 
    'SEQUENTIAL_STRICT', 
    ARRAY[
        'INSERT INTO resilient_bg_lab.evidencia_procesos (escenario, mensaje) VALUES (''ESTRICTO'', ''Tarea 1 - Exitosa'');',
        'SELECT 1 / 0; -- ERROR INDUCIDO',
        'INSERT INTO resilient_bg_lab.evidencia_procesos (escenario, mensaje) VALUES (''ESTRICTO'', ''Tarea 3 - NUNCA DEBE EJECUTARSE'');'
    ],
    p_timeout_seconds => 10,
    p_max_retries => 0
);

```

**✅ Verificación:**

```sql
-- Espere 2 segundos y ejecute:
SELECT * FROM resilient_bg_lab.evidencia_procesos WHERE escenario = 'ESTRICTO';
-- Solo debe ver el mensaje de la "Tarea 1". La tarea 3 fue bloqueada por el orquestador.

```

## 🧪 ESCENARIO 3: Concurrencia Ráfaga (Paralelo Inicial)

    'PARALLEL_INITIAL',

## 🧪 ESCENARIO 6: Reutilización de Plantillas (El Caso Juan y Roberto)

**Objetivo:** Demostrar que el histórico V5 es un *Snapshot* puro, permitiendo reutilizar y modificar Jobs sin romper la base de datos ni afectar los reportes pasados.

    ]
);

-- 2. Roberto ejecuta el Job en la noche por su nombre
SELECT resilient_bg.launch_job_by_name('PRUEBA_06_REUTILIZACION');

-- 3. Juan RE-DEFINE el Job agregando un paso nuevo (Comprobando que no hay error de llaves foráneas)
SELECT resilient_bg.create_job_definition(
    'PRUEBA_06_REUTILIZACION',
    'SEQUENTIAL_NORMAL',
    ARRAY[
        'INSERT INTO resilient_bg_lab.evidencia_procesos (escenario, mensaje) VALUES (''REUTILIZA'', ''Paso 1'');',
        'INSERT INTO resilient_bg_lab.evidencia_procesos (escenario, mensaje) VALUES (''REUTILIZA'', ''Paso 2 Agregado'');'
